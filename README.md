
# ClickTrack

ClickTrack is a REST API built with Spring MVC that allows publishers to manage their offers, create tracking links, and track the number of clicks generated by each link.

## Features

- Retrieve all publishers.
- Retrieve a publisher by ID.
- Retrieve offers associated with a publisher.
- Retrieve tracking links associated with a publisher.
- Create tracking links for a specific publisher.
- Track clicks using a dedicated tracking URL.
- Handle HTTP status codes and validate incoming requests.
- Use a layered architecture with Controllers, Services, Repositories, and Models.
- Configure Spring beans using XML and constructor injection.

## Tech Stack

- Java 17+
- Spring MVC
- Maven
- Apache Tomcat 10.1+
- XML-based Spring configuration
- In-memory data storage using Java collections

## Architecture

The project follows a layered architecture:

```text
Controller
    |
    v
Service Interface
    |
    v
Service Implementation
    |
    v
Repository Interface
    |
    v
Repository Implementation
```

- **Controller:** Handles HTTP requests and responses.
- **Service:** Contains business logic.
- **Repository:** Manages data retrieval and storage.
- **Model:** Represents publishers and tracking links.
- **Spring XML Configuration:** Defines beans and injects dependencies through constructors.

## Data Models

### Publisher

A publisher contains the following attributes:

- `id`
- `nom`
- `prenom`
- `email`
- `categorie`

Available categories include `TECHNOLOGIE`, `SPORT`, `POLITIQUE`, and `ECONOMIE`.

### Lien

A tracking link contains:

- `id`
- `publisherId`
- `offre`
- `urlDestination`
- `clicks`

New tracking links start with a click count of `0`. The click count is updated whenever the tracking endpoint is called successfully.

## API Endpoints

The following examples assume that the application is deployed under the `/track` context path.

Base URL:

```text
http://localhost:8080/track
```

### Publishers

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/publishers` | Retrieve all publishers |
| GET | `/api/publishers/{id}` | Retrieve a publisher by ID |
| GET | `/api/publishers/{id}/offres` | Retrieve a publisher's offers |
| GET | `/api/publishers/{id}/liens` | Retrieve a publisher's tracking links |

### Create a Tracking Link

**Method:** `POST`

**Endpoint:**

```text
/api/publishers/{publisherId}/liens
```

**Example URL:**

```text
http://localhost:8080/track/api/publishers/1/liens
```

**Request body:**

```json
{
  "offre": "Gaming Laptop",
  "urlDestination": "https://example.com/laptop"
}
```

The publisher ID is provided in the URL. The server associates the new tracking link with that publisher and initializes the click count to `0`.

**Expected HTTP status codes:**

- `201 Created` — tracking link created successfully.
- `400 Bad Request` — required fields are missing or blank.
- `404 Not Found` — publisher does not exist.

### Track a Click

**Method:** `GET`

**Endpoint:**

```text
/t/{id}
```

**Example URL:**

```text
http://localhost:8080/track/t/1
```

The tracking endpoint identifies the requested link and increments its click count. The response or redirect behavior should follow the requirements specified in the project brief.

**Expected HTTP status codes:**

- `200 OK` — tracking operation completed successfully, if the endpoint returns a response.
- `404 Not Found` — tracking link does not exist.

## Installation and Execution

### Prerequisites

Make sure the following tools are installed:

- JDK 17 or later
- Maven
- Apache Tomcat 10.1 or later

### Build the Project

Run the following command from the project root:

```bash
mvn clean package
```

The generated WAR file will be available in the `target/` directory.

### Deploy to Tomcat

1. Copy the generated WAR file into Tomcat's `webapps/` directory.
2. Start the Tomcat server.
3. Verify the application context path.
4. Test the endpoints using Postman or another HTTP client.

## Important Notes

- The current repositories use in-memory collections. Data created during execution is not persisted after the application restarts.
- Spring beans are configured explicitly in XML rather than through component scanning.
- Constructor injection is used to manage dependencies between repositories, services, and controllers.
- The Spring MVC configuration must be loaded correctly by the DispatcherServlet.
- All endpoints and response formats should be verified against the original project brief before submission.
